# 防模板化指南

本文件沉淀操作手册防模板化的实战经验，来自 2026 年同批多任务申报中模板化检查被反复触发的案例。所有规则服务于一个目标：同一批次提交的多份申请材料，在目录、表格、段落、小节命名上互不雷同，且单份手册读起来有节奏感而非机械模板。

## 0. 强制执行链（规则怎么生效）

本指南不是仅供模型自觉阅读的文档。可自动化的规则已下沉到脚本，在三个时机强制执行：

| 时机 | 脚本位置 | 阻断力度 | 检查内容 |
|---|---|---|---|
| 草稿写完立即 | `generate_manual_draft.py` 第 5 轮"防模板化复核"（`anti_templating_issues`） | issues 非空即 STOP_FOR_USER | 单文档重复小节、≥300 字段落、同批同构（含本任务） |
| 内容质量门禁 | `content_quality_check.py` gate 23（同批同构）、gate 24（段落节奏） | 本任务同构阻断，超长段落软提示 | 同批四类同构 + 段落长度 |
| manual 门禁确认 | `confirm_stage.py --stage manual` 内嵌 `batch_structure_check` | 阻断 | 同批四类同构（双保险） |

模型阅读本指南的时机：撰写手册之前（manual_workflow 默认读取集），用于理解规则背后的手法与示例；写完草稿后的校验不依赖模型自觉，由脚本强制。

## 1. 同批结构差异化

同批任务 = 同一提交批次目录下的兄弟任务（`草稿/操作手册.md` 互相对比）。审核员对"多份申请长得一样"极其敏感，这是补正驳回的首要触发点。

### 1.1 自动检查

`content_quality_check.py` gate 23 自动执行四项对比（同批兄弟手册）：

| 检查项 | 判定 | 触发条件 |
|---|---|---|
| 标题重合率 | 共享标题数 / 较小标题集合 ≥ 60% 阻断 | 章节骨架雷同 |
| 表格结构指纹 | 表头单元格序列哈希共享 ≥ 3 个阻断 | 表格格式套用 |
| 重复段落 | 完全相同的段落哈希共享 ≥ 3 个阻断 | 段落照抄 |
| 单文档重复小节 | 同一小节标题在本手册出现 ≥ 3 次阻断 | 模板化小节 |

兄弟任务自身的问题降级为警告不阻断本任务，但要在汇报中提示用户批次风险。

### 1.2 差异化手法

**表头差异化**：skill 强制的格式（四列操作步骤表"操作步骤/用户操作/系统响应/异常处理"）保留；其余表头按语义微调命名，改一个词即改变指纹：

- 异常情况 \| 处理逻辑 → 异常现象 \| 系统处理方式
- 功能点 \| 描述 → 界面区域 \| 内容说明
- 字段名称 \| 字段类型 \| 是否必填 \| 输入边界 \| 业务规则 → 字段 \| 控件 \| 是否必填 \| 输入限制 \| 业务规则
- 序号 \| 功能模块 \| 细分功能 \| 功能说明 → 序号 \| 功能模块 \| 细分功能 \| 说明与适用条件

**小节标题个性化**：禁止同批通用小节名（"列表界面""异常功能逻辑""操作步骤"）。按模块加前缀：

- 列表界面 → 定位终端列表 / 进出记录列表 / 摄像头设备列表
- 异常功能逻辑 → 定位卡异常处理 / 进出登记异常处理 / 摄像头异常处理
- 操作步骤 → 实时监控操作 / 搜索与跟踪操作 / 轨迹回放操作 / 报警处置操作

**文档类型避让**：同批任务逐个运行 `propose_document_plan.py`，后者自动避让前者已占用的文档类型（user_manual / design_description / hybrid）。

### 1.3 兄弟任务连带修复

同批检查是一荣俱荣：兄弟任务的重复小节会连带阻断本任务。处理顺序：先修本任务（差异化表头、个性化小节），再征得用户同意后顺手修复兄弟任务草稿的重复小节（改小节标题是低风险文本替换，不影响已生成的正式资料）。

## 2. 段落节奏

纯长段（150 字以上连续叙述）读起来没有呼吸感，纯短段则碎片化。目标形态：长短交错，首句点题。

### 2.1 拆分规则

- 单段控制在 40-120 字，超过 150 字必须按语义边界拆分。
- 语义边界 = 动作切换、角色切换、时间顺序推进、对象切换处。
- 拆分后每段只讲一个意思，首句做主题锚点，读者扫首句即知全段。
- 平均段长 70-90 字为健康区间；枚举类段落（指标清单、功能列举）可适当放宽，但仍应控制在 150 字内。

### 2.2 节奏结构

- 短段（10-40 字）点题：如"从业务链路上看，系统运行分为五段。"
- 中段（40-120 字）展开：一段一义。
- 段落开场词避免连续重复（同词开场 ≥4 次会被 human-writing 检查提示）。

## 3. 段落与表格平衡

"不要纯自然段，少量能结构化就结构化处理"——段落是叙事主体，表格承担对照信息，两者互补。

### 3.1 适合表格化的内容

段落保留一句引子，以下对照型内容用表格呈现：

| 内容类型 | 表格列设计示例 |
|---|---|
| 登录要素 | 登录要素 \| 填写说明 |
| 表单参数 | 参数项 \| 可选值 \| 作用说明 |
| 页签/分类差异 | 页签 \| 人员来源 \| 筛选方式 |
| 时间段选项 | 选项 \| 查询范围 \| 适用场景 |
| 交接班/巡查检查 | 检查项 \| 检查要点 \| 异常处理方式 |
| 状态流转 | 状态 \| 含义 \| 触发条件 \| 下一状态 |
| 大屏布局 | 区域 \| 位置 \| 展示内容 \| 刷新方式 |

### 3.2 不适合表格化的内容

- 业务链路叙述（谁→做什么→产出什么→下游谁接着用）
- 典型场景叙事（时间、地点、人物、事件的具体经过）
- 模块用途与上下游影响的说明

## 4. 截图位置与命名

### 4.1 位置规则（§8 的实战补充）

- 列表页截图：放在对应"XX列表"小节的表格之后，**禁止**放在异常处理小节里。
- 新增/修改表单截图：放在字段表之后、异常逻辑或下一操作阶段之前。
- 大屏/流程类截图：放在模块说明段之后、第一个细节小节之前。
- 登录截图：放在登录说明文字之后，不在标题正下方。

### 4.2 命名规则

截图预留名称**不要带模块名前缀**（如"「定位卡管理」新增定位卡表单截图"）。归属检查器会把含模块名的截图判定为"属于模块章节而非当前小节"，导致误报。用小节级名称（"新增定位卡表单""批量登记表单"）。

### 4.3 移动截图的正确做法

多个小节标题同名（如两个模块都有"新增界面"）时，按标题文本插入会错位。移动截图必须按"截图文本 + 前后文锚点"定位，移动后逐一核对全部截图的归属小节。

## 5. 术语表别名的子串陷阱

禁止别名用子串匹配扫描。标准名 + 动作的合法组合会被误判：

- 标准名"历史轨迹"，别名表列"轨迹回放" → 正文"历史轨迹回放"包含子串，误报。
- 处理：别名表只列真正会混淆的独立词（"路径回放"），"标准名+动作"组合不进别名表。
- 真实 UI 名称（菜单"定位卡管理"、按钮"新增定位卡"、字段"定位卡号"）不进禁止别名——它们是界面事实，不是术语混用。

## 6. 编辑安全与回读

多轮脚本化替换（全局替换、按锚点移动）容易造成三类损伤，每次修改后必须回读：

- 句子断裂：替换边界丢失标点（"，列表中显示"）
- 句序错乱：插入位置错位（"随着人员进入车间"被挪到段落末尾）
- 内容丢失：截图预留、表格行在移动中被删除（"新增摄像头表单"截图丢失）

回读重点：所有截图预留数量与归属、每段首尾完整、锚点替换后的上下文语义连贯。
