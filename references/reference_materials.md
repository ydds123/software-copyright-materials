# 参考素材约定（0+3 结构版）

> 完整方案见项目文档 `用户项目文件/docs/软著参考素材策略/参考素材与防模板化方案.md`。本文件是 skill 层面的落地规则。

## 核心原则

参考素材的三个用途方向相反，必须分开处理：

| 用途 | 机制 | 范围 |
|---|---|---|
| 主数据对齐（要一致） | 主体法定字段来自**唯一主数据表**（`用户项目文件/软件著作权资料/主数据.json`，按项目路径定位） | 著作权人、著作权人类型、权利范围、软件分类、软件说明、开发方式 |
| 项目事实（要准确） | 来自**代码/部署/用户确认**推导，不从「最近一份」复制 | 硬件环境、编程语言、源程序量、日期 |
| 质量校准（要跟上） | 固定 rubric + 少量**人工认证样本**（用户在已完成任务中标记质量锚点，见下节） | 章节完备度、写作深度 |

- 差异化必须能追溯到业务、角色、端或设计的真实差异，禁止为差异而编造。
- 章节结构由软件真实业务决定，不用「安全模板」；全批画像只用于**提示碰撞**，不提供统一替代答案。

## 已拍板的 4 项决策（v2）

1. **AI 声明空着**：不自动填「未使用 AI」，留空待人工处理。
2. **按独立软件申请**：每项各按独立软件登记，不合并、不改名；登记前记录「软件边界说明」。
3. **旧批次不处理**：已提交/已完成的旧材料不返工，冻结原始材料。
4. **检测定位**：确定性检查（文件缺失/版本漂移/错误声明）做硬门禁；相似度只出风险等级，高风险人工复核、中低风险放行。

## 检测与复检

- 确定性检查 = 硬门禁：文件缺失、草稿/正式件版本漂移、错误声明、编号错误、重复粘贴。
- 相似度检查 = 风险筛选器：高风险人工看、中低风险放行；不做共享表指纹数量的硬阈值（阈值 1 会无解）。
- 强制格式（术语表/字段表/四列操作步骤表）走白名单。
- 相似度阈值需用已标注正负样本标定（真实同构 / 强制格式 / 同域自然相似 / 改词规避）。

## 定位方式与边界

- 任务目录形如 `<项目目录>/<年份>年软件著作权申请资料/<软件全称>/`，兄弟任务即同目录下的其他任务。
- 主数据表：工作区同级的 `主数据.json`（如 `用户项目文件/软件著作权资料/主数据.json`）；不存在时由用户确认后新建。
- 认证样本（B 轨）：见工作区同级的 `认证样本清单.json`（如 `用户项目文件/软件著作权资料/认证样本清单.json`，用户已于 2026-09-08 指定 4 份质量锚点）；清单不存在时按 skill 内置 `目标态样本手册.md` 起步。
- 冷启动：无主数据、无认证样本时，退回人工填口径 + 内置样本起步。
- 用户有特殊说明（指定参照某份、或明确不用参考）时，以用户说明为准。
